# Roadmap

The roadmap is directional, not a promise of delivery dates. Community evidence can change priorities.

## 0.1 — Public preview

- Publish the standard, Codex-first reference implementation, validator, prompts, white paper, and community files.
- Collect adoption reports from new and existing repositories.
- Identify confusing requirements and overly rigid checks.
- Validate privacy and release hygiene.

## 0.2 — Adoption evidence

- Add sanitized case-study templates and benchmark guidance.
- Improve script and entry-point inventory examples.
- Add more complete examples for web applications, data platforms, monorepos, and infrastructure repositories.
- Measure onboarding time, context size, review findings, and cleanup outcomes.
- Improve the upgrade and exception workflow.

## 0.3 — Agent adapters

- Define a compatibility test suite for agent instruction discovery, skills, subagents, permissions, and review isolation.
- Accept tested community adapters for selected coding-agent environments.
- Clearly separate verified support from best-effort examples.

## 0.4 — Bootstrap tooling

- Explore a small local CLI that can inventory a repository, instantiate the governance baseline, and run validators without rewriting application structure.
- Keep the CLI dependency-light and transparent.
- Require dry-run output and explicit approval for every write.

## 0.5 — Benchmarks and ecosystem

- Publish representative repository-recovery tasks.
- Compare single-agent and executor/reviewer workflows.
- Evaluate optional codebase-memory and MCP capabilities with reproducible methods.
- Build a catalog of anti-patterns and recovery examples.

## 1.0 — Stable standard

A stable release should require:

- successful adoption across several languages and repository profiles;
- a documented compatibility and deprecation policy;
- a reliable upgrade path;
- stable normative terminology;
- tested release and security processes;
- evidence that the standard improves understanding without creating excessive process overhead.

## Explicit non-goals

- Becoming a full application framework.
- Requiring one commercial coding agent.
- Providing autonomous production access.
- Maximizing the number of skills, agents, or MCP integrations.
- Claiming certification without an auditable conformance program.
