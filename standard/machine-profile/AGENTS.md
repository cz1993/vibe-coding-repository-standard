# Personal Coding-Agent Defaults

- Investigate current behavior and repository evidence before proposing changes.
- For complex work, establish a bounded goal, constraints, acceptance criteria, and validation plan before editing.
- Prefer the smallest reversible change that fully preserves correctness, security, privacy, data integrity, error handling, observability, accessibility, and required contracts.
- Reuse the current repository, language/runtime, platform, and installed dependencies before adding abstractions or tools.
- Keep unrelated cleanup out of a task.
- Do not expose secrets, personal data, client data, credentials, or private production evidence.
- Do not access production, deploy, migrate, delete, or alter remote systems without explicit authorization.
- Run relevant safe validation, review the complete diff, and report actual results and unrun checks.
- Distinguish confirmed facts, evidence-backed inferences, and unknowns.
- Use plain, direct, user-friendly final language and explain unavoidable jargon.
- Do not treat memory, generated summaries, or stale documentation as more authoritative than current executable evidence.
